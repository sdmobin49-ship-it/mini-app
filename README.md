# Spider VPN — ربات + Mini App

Mini App روی **همان پروسه، همان دیتابیس SQLite و همان کدهای پنل** ربات اجرا می‌شود (aiohttp؛ وابستگی جدیدی لازم نیست).

## ساختار
- `webapp/` — API (`server.py`)، منطق سفارش/فعال‌سازی (`service.py`)، دیتابیس (`store.py`)، Adapter پنل (`panel.py`)،
  احراز هویت تلگرام (`auth.py`)، اتصال به ربات (`bot_hooks.py`) و فرانت‌اند بدون build (`static/`)
- `core_helpers.py` — توابع مشترک (عیناً از `handlers.py` منتقل شده‌اند)
- `tests/` — تست‌ها: `python -m unittest tests.test_webapp`

## متغیرهای محیطی
| متغیر | توضیح |
|---|---|
| `BOT_TOKEN`, `PANEL_URL/USERNAME/PASSWORD`, `UNLIMITED_PANEL_*`, `TUNNEL_PANEL_*` | اگر تنظیم نشوند مقدار فعلی `config.py` (fallback) استفاده می‌شود. **بعد از انتقال، توکن و رمزها را عوض کن و fallbackها را از config.py حذف کن.** |
| `DB_PATH` | مسیر فایل دیتابیس (مثلاً `/data/vpn_bot.db` روی Volume) |
| `WEBAPP_URL` | آدرس HTTPS عمومی (مثلاً `https://xxx.up.railway.app`) — بدون آن دکمه Mini App در ربات نمایش داده نمی‌شود |
| `PORT` | Railway خودش می‌دهد |
| `WEBAPP_SESSION_SECRET` | کلید امضای نشست (پیشنهاد: رشته تصادفی ۳۲+ نویسه) |
| `SUPPORT_URL` | پیش‌فرض `https://t.me/VpnSpiderMan` |
| `DB_WAL=1` | اختیاری: فعال‌کردن WAL. پیش‌فرض خاموش است تا vpn_bot.db همیشه تک‌فایل بماند |
| `WEBAPP_ENABLED=0` | خاموش‌کردن Mini App (فقط ربات) |
| `INITDATA_MAX_AGE`, `SESSION_TTL`, `USAGE_TTL` | اختیاری (ثانیه) |

## اجرای محلی
```
pip install -r requirements.txt
export WEBAPP_URL=https://<tunnel-https-url>   # مثلاً cloudflared/ngrok، چون تلگرام HTTPS می‌خواهد
python bot.py
```

## استقرار روی Railway (بدون سرویس جدا)
Mini App داخل **همان سرویس ربات** اجرا می‌شود؛ پس سرویس/محیط جدید و هزینه‌ی اضافه لازم نیست.
1. در همان سرویس: Settings → Networking → **Generate Domain** (HTTPS رایگان) و مقدارش را در `WEBAPP_URL` بگذار.
2. **Volume** به سرویس وصل کن (مثلاً mount در `/data`)، `DB_PATH=/data/vpn_bot.db` را تنظیم و یک‌بار فایل دیتابیس فعلی را آنجا کپی کن.
   بدون Volume، دیتابیس با هر دیپلوی به نسخه‌ی داخل مخزن برمی‌گردد و داده‌ها از بین می‌روند.
3. (روش جایگزین بدون Volume: `vpn_bot.db` کنار کد باشد و `DB_PATH` تنظیم نشود؛ قبل از هر دیپلوی ابتدا دیتابیس زنده را دانلود کن.)
4. متغیرهای بالا را در Variables بگذار و دیپلوی کن. ربات در لاگ `Mini App server listening` چاپ می‌کند.
5. پیش از دیپلوی از دیتابیس واقعی **بکاپ** بگیر. Migration فقط جدول‌های `wa_*` را اضافه می‌کند و جدول‌های قبلی را تغییر نمی‌دهد.
6. اگر Mini App خطا بدهد ربات بدون آن به کار ادامه می‌دهد (`WEBAPP_ENABLED=0` برای خاموش‌کردن کامل).

## رفتار مهم
- قیمت همیشه سمت سرور از `config.py` خوانده و در سفارش ثابت می‌شود.
- پرداخت موفق + قطعی پنل: سفارش `paid` می‌ماند و فعال‌سازی با backoff (۳۰ث، ۲د، ۱۰د، ۳۰د، ۲ساعت) تا ۸ بار تکرار می‌شود. پس از آن: پرداخت از موجودی → برگشت خودکار به کیف پول؛ پرداخت کارتی → هشدار به ادمین با دکمه «تلاش مجدد».
- تمدید حجمی: مصرف صفر می‌شود، حجم پلن جدید اعمال و زمان به انقضای فعلی اضافه می‌شود (تمدید نامحدود: فقط زمان).
- تیکت: ادمین‌ها پیام تیکت (`#T<id>`) را در ربات می‌گیرند و با **Reply** جواب می‌دهند.
- تاریخچه سفارش‌های Mini App فقط شامل سفارش‌های ثبت‌شده از خود Mini App است (سفارش‌های قدیمی ربات جدول سفارش نداشتند).
